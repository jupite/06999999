# 文章发布与人工审核

## 站主发布

1. 登录后点击“写文章”，或从“我的文章”的“草稿”筛选继续编辑。
2. 填写非空标题与正文，先点击“保存草稿”。
3. 没有未保存修改时，“直接发布”按钮可用；确认后文章立即公开。
4. 发布成功后进入 `/articles/[slug]`，游客可从 `/articles` 列表阅读。

## 普通用户投稿

1. 保存草稿后点击“提交人工审核”。当前 AI 审核执行器尚未接入，所有普通用户投稿明确转人工。
2. 提交后前往 `/my-articles` 查看状态与正文；待审核内容只有本人和站主审核入口可查看。
3. 被拒绝时可查看原因，点击“复制为新草稿修改”，修改保存后重新投稿。原稿与审核记录保留。

## 站主审核

1. 从 `/admin` 点击“文章审核”，或直接访问 `/admin/reviews`。
2. 打开投稿阅读正文，在审核说明中填写意见。
3. “通过并发布”会立即公开当前审核版本；“拒绝投稿”必须填写原因。
4. 审核时重新检查站主权限及投稿作者的封禁、发布权限；已审核或已变化的版本不能重复审核。

## 编辑已发布文章

1. 在“我的文章”的“已发布”筛选中点击“编辑文章”，修改标题或 Markdown 正文。
2. 站主点击“发布修改”后，原文章地址立即展示新版本。普通作者点击“提交修改审核”，可从“待审核”筛选查看进度。
3. 审核期间及拒绝后，访客仍看到上次发布的版本。审核通过后，原文章地址展示新版本。修改被拒绝时，作者可查看原因并在原文章上修改后重新提交。
4. 编辑内容在提交时保存。删除已发布文章也会取消该文章待审的修改。

## 实现与边界

- 复用 Content、ContentRevision、ModerationReview、AuditLog，无新增迁移。
- 草稿提交、审核状态、发布版本指针及记录在数据库事务中写入；操作按内容行串行化并重新检查版本状态。
- 普通用户不能审核，不能替别人投稿；自己的草稿状态由服务端读取，客户端不能指定“免审”。
- 公开列表、详情和标题元数据仅使用 publishedVersion 指向的 PUBLISHED 版本，不读取最新私有草稿替代它。
- 正文使用 Markdown 安全渲染，跳过原始 HTML；图片上传尚未开放，Markdown 图片显示提示。
- 发布后可在“我的文章”的“已发布”筛选中删除自己的文章；确认后退出公开展示和个人列表，数据库保留内容和审核记录，暂无恢复入口。首次投稿被拒绝时可通过复制为新草稿修改。
- 列表每页 20 篇，提供上一页和下一页。发布时间取发布审核记录，显示 UTC+8。
- 账号被封禁后不能新投稿或通过审核；已发布历史内容暂保留，后续下架功能单独处理。

## 验证

```powershell
pnpm test
pnpm test:articles
pnpm typecheck
pnpm build
```

`test:articles` 运行草稿及发布审核数据库集成测试，创建临时测试用户与内容，最后事务回滚。覆盖匿名、越权、封禁、显式禁止、版本冲突、重复操作、拒绝重投、公开版本隔离与审核记录。不会发布或删除真实用户文章。

已验证类型检查、生产构建、9 项规则测试、3 项数据库集成测试，以及匿名访问页面和不存在文章的 404。真实登录浏览器中的按钮交互仍可按上面的步骤验收。
