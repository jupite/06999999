# 文章图片上传

## 配置

1. 在 `apps/web/.env` 设置 `MEDIA_ROOT`，使用部署目录之外的绝对路径。运行 Next.js 的账号需要读写该目录，修改配置后重启服务。反向代理应通过应用访问图片，并允许与后台单张上限相符的请求体大小。
2. 站主从「站点管理 → 图片与上传配额」配置单张上限和全站容量，单位为 MiB。单张上限允许设为 0 到 20 MiB。全站上限或单张上限为 0 时暂停新增上传。
3. 按 GitHub 数字 ID 查找已登录过本站的用户，开启图片上传并设置个人容量。站主也需要个人额度。后台会显示用量和剩余容量，设置变更会写入审计日志。

## 上传和审核

在文章编辑器点击「上传图片」，选择 JPEG、PNG 或 WebP。图片会转为 WebP，移除原始元数据并按需缩小。编辑器会在正文末尾插入 Markdown 图片语法，可在预览区确认效果。填写图片描述后保存草稿或提交修改。

上传的图片先对作者和站主开放。只有当前公开版本引用的图片会对访客开放。修改待审期间，访客继续看到旧版图片。删除文章或通过新版本移除图片后，旧图随公开引用撤销。如果还有其他文章的当前公开版本引用旧图，访客仍可访问。文章只能引用作者本人上传的图片，外部图片地址显示占位提示。

## 配额与存储

- 容量按实际落盘的 WebP 字节计算，同一资源被多个版本引用时计一次。单张限制同时约束上传原图和落盘文件。
- 上传事务锁定全站额度和用户记录，在写入文件前重新检查权限、个人额度、全站额度与磁盘剩余空间。文件写入、媒体记录和已用额度全部成功后才返回上传地址。
- 调低额度或撤销权限只影响新增上传。现有图片和审核版本继续保留。当前也保留上传后未引用的图片，这些文件仍计入额度。图片回收入口和进程中断后的残留文件清理待接入。

可用 `pnpm test:media` 运行集成测试。测试在本地开发数据库创建隔离 schema，并使用临时目录保存图片。测试结束时清理两者，数据库账号需要在开发库中创建 schema 的权限。
