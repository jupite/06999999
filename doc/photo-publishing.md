# 照片墙投稿与审核

照片墙 `/zh/photos`、`/en/photos` 展示已公开照片，每页 20 张，支持分类和标签筛选。分类/标签选项只来自已公开照片，不泄露待审元信息；照片显示作者、标题和纯文本说明。

## 投稿

从「投稿照片」进入，必须同时有 `photo.submit` 和统一的 `image.upload` 权限。先上传一张 JPEG、PNG 或 WebP，复用现有图片 API、格式转换、全站限额及个人容量。选择已存在的分类，可填写最多 5 个标签，每个最多 32 字；分类由站主管理，与文章共用词条。

标题最多 160 字，说明最多 2000 字。只能提交本人已上传且可用的图片，不接受外部 URL 或其他用户的图片。站主直接公开，普通用户进入人工审核；AI 执行器尚未接入。

「我的照片」分页展示本人投稿、审核状态及拒绝原因。相同提交标识与相同输入重试不会新建内容；改动输入后需重新发起投稿。当前不提供草稿、编辑、删除和批量上传，也不创建独立相册。

## 审核与图片可见性

后台「照片审核」逐条通过或填写原因拒绝。通过前重新检查作者账号、照片权限、上传权限、图片归属及可用状态；旧页面无法重复审核。审核与操作记录保留，概览计入待审照片。

待审图片仅作者和站主可读取；审核通过后随对应公开版本展示。共用图片若已经被其他公开内容引用，则沿用原有公开可见性，不能因新的投稿待审而收回公开图片。上传文件计入原有额度，更换文件或投稿被拒绝不会自动删除文件或返还容量；媒体回收另行实现。

## 配置与接口

上传前在媒体设置配置全站和单文件限制、个人上传额度，以及服务端 MEDIA_ROOT。额度为 0 不允许新增上传。本地管理员通过账号标识 `local:admin` 配置个人额度，原有 GitHub 数字 ID 继续可用。

文件上传使用 `POST /api/media`，图片读取使用 `GET /api/media/{id}`，契约见 [Web API](./api/web.openapi.yaml)。投稿与审核使用服务端 Action，每次重新检查权限，不新增 HTTP 业务接口。

## 验收

`pnpm test:photos` 检查图片归属、分类标签可见性、重复提交、拒绝、撤权与封禁，并在隔离数据库 schema 中验证真实图片上传、个人额度和审核前后图片访问。测试数据回滚或清理。
