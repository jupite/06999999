## 建议部署方式（待实机检查后落定）

```text
互联网 → 域名 / HTTPS → Nginx → Next.js
                                  ├─ PostgreSQL
                                  └─ FastAPI
```

- 通过选定的运维方式管理 Nginx 与证书；Next.js、FastAPI 建议通过 systemd 管理，避免与面板重复管理同一进程。
- 业务公开入口使用 HTTP/HTTPS；SSH 和面板管理入口单独限制访问。
- 应用服务和数据库优先监听回环地址，不直接暴露业务内部端口。
- Python 初期单 worker；不默认部署 Redis、队列或大型本地模型。
- 服务器内存由所有进程共享，是否足够必须结合现有服务和实际负载检查，不能据此承诺并发容量。
- 优先在匹配服务器系统和 CPU 架构的 Linux CI 环境构建 Next.js，部署运行产物；不直接复制 Windows 构建中的原生依赖到 Linux。
- 备份数据库并保存到服务器之外；设置日志轮转，检查媒体文件及备份对磁盘的占用。
- 发布前确定环境变量、迁移执行步骤、健康检查和回滚方式；破坏性迁移需单独评估恢复路径。

## 部署前需核实

1. 域名、DNS 管理方、是否使用 www、是否需要测试域名。
2. SSH 用户、端口、已有密钥或本机 SSH 配置；不要把密码或私钥写入仓库。
3. 实际 Linux 发行版、CPU 架构、内存和磁盘余量。
4. 面板/Nginx/数据库现状，是否承载其他网站或服务。
5. 已占用端口、防火墙和云侧规则。
6. 代码仓库、CI 平台、发布触发方式和应用运行账号。
7. 数据库及文件备份目的地、保留周期、可接受的数据丢失和恢复时间。
8. 服务器续费负责人及提醒需求；目前未设置续费提醒。
