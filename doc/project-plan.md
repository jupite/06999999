# 个人网站项目规划

更新日期：2026-10-01。

## 已确认目标与决策

- 建设个人网站；长期保留多风格与布局扩展能力，首版只实现二次元风格。
- 首版确定为完整二次元个人站，包含首页、项目、文章、照片墙、音乐、友链、关于七个栏目。
- 首版只实现二次元风格，其他风格后续扩展。角色视觉方向确定为《魔法少女小圆》的晓美焰，配色与布局参考见 [视觉规划](./visual-direction.md)。
- 增加网站内可拖动悬浮宠物，形象为长发、黑发带经典造型的平滑 Q 版动画小焰，提供交互，不开发系统桌面程序。
- 支持 GitHub 登录和用户投稿；图片上传统一由站主授权，覆盖照片墙、文章插图和项目封面等入口，并为每位用户设置容量上限。
- 项目采用外链展示卡片，站主可配置允许提交的项目域名，默认精确匹配，可逐条开启包含子域名；未匹配则禁止提交。
- 网易云音乐同时支持单曲和歌单；站内切页保持播放，缩小为可拖动悬浮组件，支持暂停、继续和切歌；具体播放接入待验证。
- 用户内容统一进入对应栏目；其他用户添加的文章、项目、照片、音乐、友链和评论均先经 AI 审核，未通过转站主人工审核；详细规则见 [发布权限与交互规划](./publishing-rules.md)。
- 建立用户权限管理系统，支持分别配置权限、白名单和黑名单，保留统一图片上传权限及每用户容量上限；详见 [权限系统](./permission-system.md)。
- 已确认权限规则：账号封禁和显式禁止优先；白名单不绕过容量、项目网址或 AI 审核；图片上传统一授权；后台显示权限生效原因。
- 文章采用 Markdown 编辑并预览。
- 文章与照片内容支持分类和标签；独立相册结构未确认。
- 支持点赞，点赞无需 AI 或人工审核；首版加入评论，GitHub 登录后提交，其他用户评论经 AI 初审，未通过转人工。
- AI API 地址、模型、密钥及审核规则由站主在后台配置；供应商后续选择，未配置时转人工审核。
- 站主本人发布内容免审、可直接发布；其他用户继续执行既定审核流程。
- 每用户图片总容量、单张图片大小及全站图片总容量支持后台设置与变更，初始数值后续配置。
- 使用数据库持久化网站数据；图片确定保存在服务器本地磁盘，数据库记录文件元信息。
- Next.js 同时负责前端与网站后端；Python 负责一部分独立后端能力，长期共存，不以更换技术栈为目标。
- 技术栈沿用讨论最后确定的组合：Next.js、TypeScript、Prisma、PostgreSQL、FastAPI。
- JS/TS 使用 pnpm，Python 使用 uv；采用轻量 Monorepo，不在初期引入 Turborepo。
- 部署目标为自有服务器；不以 Sites 托管或 Vinext 替代官方 Next.js。
- 具体软件版本尚未选定；初始化时核实兼容性并通过锁文件固定依赖。

## 架构基线

以下为此前提出的职责划分，作为实现基线；具体功能是否进入第一版，见待确认事项。

| 模块 | 职责 |
| --- | --- |
| Next.js 前端 | 公开页面、管理后台页面、二次元布局、SEO；多风格切换留待后续 |
| Next.js 后端 | 网站登录与权限、个人资料、文章、项目、站点配置、Python 调用入口 |
| PostgreSQL + Prisma | 网站业务数据、由 Next.js 管理的数据迁移 |
| FastAPI | 建议首先承接全栏目内容 AI 审核调用；职责分配及供应商待确认，其他专项功能不默认加入 |
| Python 持久化 | 仅在专项功能需要时引入，使用独立表或 schema，迁移方案届时确定 |

调用关系：浏览器 → Next.js → PostgreSQL；需要专项能力时由 Next.js → FastAPI。

核心约束：

1. 同一项业务明确唯一负责方，不在两端重复实现规则。
2. 网站内容由 Next.js 管理；Python 返回处理结果，由 Next.js 决定是否写回网站数据。
3. 同一张表只由一套迁移工具管理；Python 不同时使用另一套 ORM 修改 Prisma 管理的结构。
4. 浏览器优先访问 Next.js；服务间调用需要认证、超时及可理解的错误处理。
5. 管理操作在服务端校验权限；不能依赖隐藏按钮或后台路径保护数据。
6. 如果出现耗时任务，再设计任务状态和独立执行进程，首版不预先引入队列。

## 多风格设计建议

采用“一套内容，多套展示方案”，区分四层：

- 内容：个人资料、项目、文章等。
- 主题：配色、字体、圆角、阴影、装饰。
- 布局：导航、网格、分区顺序和响应式排列。
- 预设：将主题、布局、动效组合成可切换的完整风格。

首版仅实现二次元预设，保留后续扩展结构，不实现多风格切换。外观使用 CSS Variables + CSS Modules；Tailwind 是否使用仍待确定。

内容获取与布局分离；布局接收统一数据，不各自查询数据库。共享基础交互和内容类型，允许不同风格分别实现外观。切换布局时保留必要的页面状态。

异形布局优先采用 CSS Grid 和局部装饰，手机端回归清晰阅读顺序。考虑减少动效偏好、键盘操作、首屏主题闪烁和按需加载图片/特效。

## 建议目录

```text
apps/
  web/
    src/
      app/                  # 页面、布局、Route Handlers
      features/             # 各业务模块
      appearance/           # 风格预设、主题、布局
      components/           # 公共 UI
      server/
        services/           # 网站业务逻辑
        db/                 # Prisma 访问
        python-client/      # Python API 调用
    prisma/                 # 网站数据模型、迁移
  python-api/
    src/
      api/
      services/
      schemas/
    tests/
    pyproject.toml
infra/                      # 部署配置，按需要添加
doc/
pnpm-workspace.yaml
pnpm-lock.yaml
```

pnpm workspace 管理 JS/TS 包，uv 管理 Python。只有存在真实复用需求时才添加 packages；两个服务可以独立更新和重启。

## 内容模型候选

候选模型包括 User、Account、Session、Profile、Project、Post、Photo、Track、FriendLink、SiteSettings、Media、Comment、Like、Category、Tag 及对应内容关联。GitHub 账户关联、内容作者归属及编辑权限需要纳入设计；具体字段在数据库设计阶段确定；音乐同时需要单曲与歌单类型及来源标识，Track 不能只覆盖单曲。

登录用户与站主管理员区分权限；普通用户只能修改自己的内容。GitHub 登录不自动授予站点管理权限。其他用户投稿统一采用 AI 审核后人工兜底；跨设备偏好同步尚未确定。

## 建议实施顺序

1. 按已确认范围初始化基础工程；同步验证音乐接入、准备宠物素材，不将可后续配置项设为开工门槛。
2. 初始化 Next.js、数据库及 Monorepo；Python 有实际接口需求时实现对应能力。
3. 跑通公开展示与后台编辑的最小完整流程。
4. 完成二次元视觉、宠物、移动端适配及必要交互验证。
5. 按部署规划接入服务器、域名、HTTPS 与备份，完成上线验收。

基础工程已开始，实际完成范围见 [开发进度](./development-status.md)。不会因存在待确认的可选功能而默认加入搜索、额外登录方式、AI 聊天或采集功能。
