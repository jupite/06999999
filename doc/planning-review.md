## 实现前必须解决的技术边界

### 网易云音乐（最高优先级可行性验证）

需要实际验证单曲/歌单信息、曲目队列、可用播放资源与程序控制。嵌入页面能显示，不等于可以自定义暂停/切歌。验证失败必须说明未满足的体验，不能以外链跳转冒充完成悬浮播放器。此项不阻塞登录、内容和数据库开发。

### 审核状态与任务可靠性

建议 Next.js 持久化投稿版本与审核状态，Python 只返回结果。提交后不依赖浏览器保持在线；进程重启或请求超时不能丢失投稿。可先采用数据库任务记录和受控处理进程，不强制增加 Redis。

必须处理重复结果、旧版本结果、人工已裁决、撤稿、封禁及服务异常。公开前校验当前版本和发布资格，失败保留待人工状态，不让旧 AI 结果覆盖人工决定。AI“通过自动发布”和故障转人工仍为建议默认行为，未误标为用户单独确认。

### 媒体访问与存储一致性

文件和数据库不能依靠单一数据库事务同时提交，需要上传预留、临时文件、完成状态及失败清理。审核图片必须能在服务端读取，不应把待审图片暴露为公开静态文件。

建议同一文件被已发布内容引用时可公开；新的未发布版本引用不改变既有公开版本的可用性。撤稿后检查是否还有公开引用，再决定收回媒体访问。外链图片策略未定，不能默认安全绕过上传授权或审核快照。

### 宠物素材

平滑 Q 版经典小焰、长发黑发带已确认，但可动画化素材未制作。先确定精灵帧/分层方案或 Live2D 适配；不能将一张静态图整体上下移动就当作完整角色动画交付。具体动作仍为建议，首版预览可细化。

## 不需阻塞开工的事项

- 网站名称、首页昵称、实际文章与项目素材：可先用明确标记的临时内容。
- 用户容量、单文件限额、全站容量、首批项目域名：后台配置；未配置时关闭对应上传/项目提交，不默认无限开放。
- AI 供应商、模型和规则：配置前采用已确认的人工审核兜底。
- 样式库、权限实现细节、版本锁定：属于工程选择，初始化时检查兼容性，无需逐项向用户询问。
- 评论和点赞的开放栏目、回复层级、分类标签创建权限：在对应模块实现前选定范围；目前不得声称已经确认所有栏目或多层回复。
- 搜索、歌词、浅色模式、独立相册、AI 宠物对话等未确认，不自动扩展首版。

## 上线前配置

GitHub OAuth 应用与回调、可信站主账号 ID、域名与 HTTPS、服务器接入、正式容量值、数据库与媒体异机备份目的地及恢复检查。服务器具体信息继续不写入仓库。

## 建议最小验收清单

- 所有已确认栏目可访问，手机/桌面可操作；站主与普通用户展示身份明确。
- GitHub 登录、封禁生效、单项禁止优先、内容归属检查、站主免审及点赞免审。
- 其他用户投稿在审核前不公开；AI 未配置转人工；旧版本/重复结果不能错误发布。
- 项目域名精确匹配、可选子域名，拒绝伪装相似域名。
- 各入口统一图片授权，用户/全站配额与并发上传检查，降低额度不删除历史文件。
- Markdown 预览与发布一致，分类标签筛选不暴露草稿；评论经过相同审核规则。
- 网易云单曲/歌单、跨页不断播、拖动和控制、不可播放提示；未验证不标完成。
- Q 版宠物动作可运行、拖动可恢复、不会遮挡手机核心按钮。
- 部署更新保留媒体文件，备份能够恢复数据库与对应图片。
