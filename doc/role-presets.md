# 角色预设与分配

站主从 `/zh/admin/roles` 或 `/en/admin/roles` 管理角色，用户详情中分配、替换或解除角色。每个普通用户最多一个角色，不做多角色叠加或角色继承。站主身份继续由本地 OWNER 账号或可信 GitHub ID 决定，不接受业务角色分配。

## 权限

每项业务能力可设继承、允许、禁止；继承回退普通用户默认规则。个人例外优先于角色，因此个人允许可以覆盖角色禁止，个人禁止也能覆盖角色允许。

判定顺序为账号封禁 → 全站关闭 → 个人设置 → 角色预设 → 默认规则，之后仍需校验内容归属、容量、项目网站名单和审核条件。角色允许上传不自动分配容量；媒体额度页提供继承/允许/禁止，保存额度时可以继续继承角色。

角色不能配置 site.manage，普通用户不能管理后台或审核内容。music.submit 仅保留业务能力规则，不因此开放站主管理的音乐导入。角色修改或分配在后续请求生效，不需要重新登录，也不写入长期 JWT。进行中的请求不承诺被即时取消。

## 管理

- 角色名去除首尾空白并规范为 NFC，最多 64 字且不能包含控制字符；同名拒绝。
- 修改按原版本校验，permissions 字段出现时整体替换该角色预设；空对象表示全部继承。
- 删除需确认、原版本匹配，且没有任何用户分配到该角色（包括封禁账号）。数据库外键及事务保护并发分配，不能产生失效关联。
- 分配按原角色 ID 校验，null 表示解除；不改变用户已有个人允许/禁止。角色变更不会自动重写个人设置或上传额度。
- 用户列表可按角色或未分配筛选，角色编辑页可跳转查看已分配用户。
- 用户详情显示角色、角色规则、个人设置、最终允许/拒绝及原因；只允许站主查询这些明细。
- 创建、修改、删除、分配均记录审计，用户详情保留分配记录。

## 接口与迁移

已实现 Web OpenAPI 中的角色 CRUD、`PUT /api/admin/users/{id}/role` 和 `GET /api/admin/users/{id}/permissions`。写入需站主会话并校验同源，JSON 请求最多 8 KiB。PATCH 使用 expectedVersion，删除在查询参数提交 expectedVersion，分配使用 expectedRoleId，避免旧页面覆盖。

新增迁移 `20261114000000_permission_roles`，上线前执行 `pnpm db:deploy` 并重新生成 Prisma 客户端/重启服务。既有用户关联默认为 null，不自动创建或分配角色，原授权保持不变。

## 验收

`pnpm test:roles` 在独立 schema 中检查权限优先级、真实上传和投稿、分配冲突、角色版本、使用中删除及并发删除/分配，测试结束清理数据和临时文件。
