# 当前 i18n 方案

## 语言选择

页面语言由 URL 的第一段决定。例如 `/zh/articles` 显示简体中文，`/en/articles` 显示英文。分享带语言前缀的链接时，接收者会看到该链接指定的语言。

顶部导航切换语言时会保留当前页面、查询参数和锚点，并通过 Server Action 将选择保存到 `site-locale` Cookie，有效期一年。旧地址如 `/`、`/articles` 和 `/write?id=…` 由 [Proxy](../apps/web/src/proxy.ts) 按 Cookie 偏好临时重定向。没有有效偏好时使用 `zh`，已有查询参数会保留。

| 界面语言 | URL 前缀 | 词典                                                 |
| -------- | -------- | ---------------------------------------------------- |
| 简体中文 | `/zh`    | [zh.json](../apps/web/src/i18n/dictionaries/zh.json) |
| English  | `/en`    | [en.json](../apps/web/src/i18n/dictionaries/en.json) |

## 项目结构和词典加载

- `apps/web/src/app/[lang]/` 包含根布局、页面和页面操作。中文和英文共享页面代码。
- `apps/web/src/app/api/` 提供 API。GitHub OAuth 回调仍使用 `/api/auth/callback/github`。
- `apps/web/src/i18n/dictionaries/` 保存各语言 JSON。文件名与 URL 语言代码对应。

[服务端加载器](../apps/web/src/i18n/server.ts)通过 `next/root-params` 读取根参数 `lang`，校验后动态导入词典。服务端组件用词典渲染界面和页面元数据。根布局设置 `<html lang>`，并通过 [LocaleProvider](../apps/web/src/i18n/client.tsx) 将词典传给客户端组件。

站内页面链接使用 `LocaleLink`。客户端或服务端代码需要跳转时，用 `localePath(locale, path)` 生成带语言前缀的地址。公开文章在两种语言界面下读取同一已发布版本。

文章日期根据 locale 格式化，统一采用 `Asia/Taipei` 时区。文章标题、正文和人工审核意见按原文展示。

## 维护词条

- 词条键只使用英文字母，采用小驼峰命名，例如 `authorLabel`。两份 JSON 使用相同的键，翻译写在值里。页面使用 `t("key")` 读取 `messages` 中的词条。
- 需要插值时，两份词条使用相同的参数名，例如 `{author}`。调用时将参数传给 `t`，例如 `t("authorLabel", { author })`。
- `system` 保存权限和错误提示。服务端返回稳定的词条键，例如 `accountBanned`，界面根据当前语言显示译文。
- 运行 `pnpm typecheck` 和 `pnpm test` 检查词典键及调用。修改路由时，在浏览器直接访问两种语言地址，并检查语言切换和旧地址跳转。
