# GitHub 登录与会话

另支持[预设账号密码登录](./password-login.md)，两种入口共用站内会话。

## 用户入口

- 访客从顶部「登录」进入 `/zh/login` 或 `/en/login`，点击「使用 GitHub 登录」。GitHub 处理账号登录和授权，网站接收授权结果。
- 授权成功后回到发起登录时所用语言的首页。顶部入口显示头像或昵称，点击可查看站内账号状态和退出登录。
- 站主在账号页可进入管理后台。普通用户的操作范围由站内权限规则决定。
- 退出登录会结束当前浏览器的站内会话，并返回同语言的登录页。GitHub 的登录状态由 GitHub 自己维护。

## 登录流程

1. 登录按钮通过 NextAuth 发起 GitHub OAuth。浏览器跳转 GitHub，用户在 GitHub 完成授权。
2. GitHub 将浏览器带回 `/api/auth/callback/github`。Next.js 服务端用授权码向 GitHub 换取访问令牌并读取账号资料。这一步依赖运行 Next.js 的环境能访问 GitHub。 [GitHub OAuth 授权流程](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps#web-application-flow)
3. 网站用 GitHub 数字 ID 查找站内账号。已封禁的账号拒绝登录。首次登录创建账号，后续登录更新显示名称和头像。
4. NextAuth 通过 Cookie 保存 JWT 会话，记录 GitHub ID 和当前的会话版本。之后站内受保护的页面和操作会在服务端重新读取账号状态和权限。

## 登录与授权的区别

| 状态     | 站内行为                                                                              |
| -------- | ------------------------------------------------------------------------------------- |
| 访客     | 浏览公开页面。访问受保护入口时提示登录。                                              |
| 普通用户 | 使用已开放且有权限的站内功能。                                                        |
| 站主     | GitHub 数字 ID 与服务端 `OWNER_GITHUB_ID` 匹配，并通过 `site.manage` 检查后访问后台。 |
| 封禁     | 拒绝建立新会话，现有会话也会因版本变化失效。解封后需重新登录。                        |

更改昵称或 GitHub 用户名不会改变站主身份。单项权限的变更在后续请求中生效。账号封禁、权限优先级和后台操作见[用户权限管理](./permission-system.md)。

## 验收

1. 在未登录窗口访问受保护页面，确认要求登录。点击 GitHub 登录，确认授权页可打开，完成真实授权后回到对应语言的首页。
2. 刷新页面，确认头像或昵称仍显示。进入账号页，确认普通用户和站主的入口分别符合权限。
3. 使用专用普通测试账号验证封禁会使旧会话失效，解封后需重新发起登录。
4. 从账号页退出后再次打开受保护页面，确认站点要求重新登录。

排查时分别记录授权页能否打开、回调能否收到 GitHub 响应、真实账号授权后会话是否有效。前两步通过后仍需完成真实账号验收。环境变量、启动和故障排查见[本地 GitHub OAuth 配置](./github-oauth-local.md)。
