# 发布权限与交互规划

更新日期：2026-10-01。

## 已确认需求

- 宠物仅存在于网站中，可拖动悬浮并提供交互，不制作系统桌面程序。
- 音乐来源为网易云音乐。
- GitHub 登录用户可发布自己的内容，各类发布入口均需根据具体权限开放。
- 项目采用展示卡片，点击跳转项目网页；站主可以设置允许添加的项目网站。
- 图片上传使用统一权限，由站主授权，覆盖照片墙、文章插图、项目封面等全部图片上传入口；每位用户独立设置容量上限。
- 所有内容统一进入对应栏目，显示作者，不单独建立个人发布空间。
- 音乐由站主在后台导入。其他用户投稿的规划覆盖文章、项目、照片、友链和评论，先经 AI 审核，未通过时交给站主人工审核。

- 站主本人发布内容免审，可直接发布，无需 AI 初审或人工复审。免审不自动赋予其他用户。

## 权限实现建议

统一权限和名单规则以 [用户权限系统](./permission-system.md) 为准。功能允许不代表免审，且不能绕过配额和网站规则。

采用“身份 + 统一图片上传权限 + 每用户容量上限”，避免把图片上传权限和管理员权限混为一谈。

| 类型               | 建议权限                                                   |
| ------------------ | ---------------------------------------------------------- |
| 未登录访客         | 浏览公开内容、使用音乐和宠物交互                           |
| 登录用户           | 提交自己的文章、符合白名单的项目及友链，按栏目规则进入审核 |
| 资源发布获授权用户 | 在基础权限上增加统一图片上传能力，受本人容量上限约束       |
| 站主               | 配置白名单、授予/撤销资源权限、人工审核及全站管理          |

已确认使用统一图片上传开关，不分别设置照片墙、文章插图、项目封面的上传权限。图片确定存储在服务器本地；具体容量数值、单文件限制尚未确定。

所有内容记录作者；用户只能编辑自己的内容，站主管理全站内容。首页编排、关于页及全站设置不属于普通用户可修改的个人内容。

## 统一图片权限与容量管理

已确认：站主为每位用户开关图片上传权限，并设置该用户的总容量上限。所有图片上传入口共用同一份容量，不按栏目分别计算。

建议实现细节（尚未逐项确认）：

- 后台显示上传权限、容量上限、已用容量与剩余容量，并允许站主调整。
- 新用户默认关闭上传；授权时设置明确配额，不默认无限容量。
- 按实际保留的图片文件及衍生图占用字节计入配额；草稿、待审、已发布文件都占容量，同一资源被多处引用不重复计量。
- 上传前预留容量，完成后按实际占用结算，防止并发上传绕过限额；失败或过期预留释放，遗留文件清理。
- 降低额度至已用容量以下时，阻止新增上传，不自动删除现有图片；撤销权限同样不自动删除历史内容。
- 文件实际删除后释放容量；仍被文章、卡片或保留版本引用的文件不能因删除一个引用就释放额度。
- 容量上限不替代单文件大小、像素尺寸和上传频率限制；这些数值在实现前确定。
- AI 审核通过不授予上传权限，也不增加容量；待审文件遵守非公开访问规则。

## 后台可变更上传限制

已确认：每用户图片总容量、单张图片大小和全站图片总容量均可在管理后台设置并变更，不写死在代码中。初始数值后续配置。

已确认生效规则：调整后的限额约束新增上传；调低限额保留已有图片，不自动删除。

建议实施规则：

- 站主管理全站单文件限制和媒体总容量，在用户详情单独调整每用户总容量；修改记录操作者、时间及前后值。
- 限制变更应用到后续上传请求；调低至当前用量以下不删除历史图片，只阻止不满足条件的新增上传。调高后在其他权限和容量条件满足时允许继续上传。
- 保存设置时校验数值范围与单位，明确显示已用/剩余容量；未设置有效限额时不默认为无限上传。
- 上传预留与最终落盘检查使用服务端有效配置，并正确释放失败预留，避免并发上传超额。
- 系统磁盘安全余量仍作为独立限制，不能因后台调大全站配额而绕过。

## 图片本地存储

已确认：图片使用服务器本地磁盘存储，不使用对象存储作为首版图片存储。

实现建议：

- 上传目录独立于代码仓库、构建产物与发布目录，通过服务端环境配置指定；部署更新不覆盖或删除媒体文件。
- 数据库保存资源 ID、所有者、相对存储键、类型、实际大小及审核/引用状态，文件保存在磁盘。使用服务端生成的文件名，不让用户输入控制磁盘路径。
- 文件不直接放入 Next.js public；由媒体访问层检查公开状态，作者与站主可访问草稿/待审资源，其他访客只能访问已发布资源。使用 Nginx 转发文件时，内部文件路径不得直接公开绕过检查。
- 本地图片供 AI 审核时，通过服务端读取并使用所选接口支持的方式提交，不为审核而暴露待审文件。
- 每用户配额之外设置全站媒体上限和磁盘剩余空间阈值；空间不足时停止新增上传，不自动删除已有内容。具体阈值待设置。
- 备份建议同时覆盖数据库和媒体目录，采用可恢复的一致性方案并保存异机副本；在线文件位于本地不代表备份只能放本机。目的地和周期待确认。
- 删除文件后更新容量统计，配合清理失败上传及校对文件/数据库记录的维护机制。

## 项目网站白名单

已确认：站主在后台添加允许的域名，默认精确匹配；每条规则可单独开启“包含子域名”，未匹配允许规则的网站禁止提交。白名单为空时没有匹配项，禁止项目提交。

站主可从「站点管理 → 项目网站名单」添加允许或禁止规则，并逐条调整子域名范围和启用状态。填写域名，例如 `example.com`。域名会统一小写，国际化域名转换为 ASCII。需要更换域名或规则类型时，可添加新规则后停用旧规则。

使用同页的「检查网址」输入完整 URL，可以查看允许、禁止、未命中或格式错误的结果。规则只检查域名，支持 HTTP 和 HTTPS，含用户名、密码或非默认端口的地址无法通过。同一地址命中允许和禁止规则时，以禁止为准。检查在本地解析 URL，不会请求目标网站。规则变更会记录操作者和变更内容。

项目卡片投稿和审核已接入同一套规则。操作步骤见[项目卡片发布](./project-publishing.md)。可用 `pnpm test:projects` 在开发数据库验证规则行为，测试数据随事务回滚。

其余实现建议：

- 路径范围属于后续可选细化，尚未确认为首版要求。
- 服务端解析 URL 并验证协议、主机和路径，不能仅用字符串包含判断域名。
- 新增或修改项目地址都重新校验。开启包含子域名时按域名边界匹配，不接受仅字符串后缀相似的其他域名。
- 首版不自动抓取项目页面或生成截图，卡片先采用用户填写的标题、介绍和地址；封面受资源权限约束。
- 白名单只能验证提交地址，不能保证外部网站后续不跳转或不变更内容。
- 其他用户项目提交同样先经 AI 审核，站主本人免审；规则变更后已有卡片的处理方式待确认。

## 点赞

已确认：支持点赞，点赞不进入 AI 或人工审核流程。该例外不改变文章、项目、照片、音乐、友链等内容投稿的审核要求。

实现建议：GitHub 登录后可点赞/取消点赞；每用户对同一内容最多一条有效点赞记录，仅对可访问且已公开内容操作，服务端校验账号状态与操作权限。具体可点赞的栏目待确定。评论按下述独立规则处理。

## 评论

已确认：首版支持评论，GitHub 登录后可提交；其他用户评论先经 AI 初审，未通过转站主人工审核。站主本人评论沿用免审规则；未配置 AI 时转人工，点赞继续免审。

实现建议：

- 评论关联具体内容和作者，独立记录审核状态；审核通过前不计入公开评论数量，也不公开展示。
- 评论内容纳入同一审核记录与待审列表；AI 不确定、调用失败转人工，自动发布行为遵循统一审核配置。
- 账号封禁、评论发布权限由服务端校验；用户只能修改自己的评论，修改后重新审核，不能绕过待审版本控制。
- 权限系统增加 comment.submit，默认普通登录用户可提交；单用户仍支持继承、允许、禁止。
- 第一版建议纯文本评论；支持哪些栏目、回复层级、通知及是否可上传图片尚未确定，不默认扩展。

## 分类与标签

已确认：文章与照片内容支持分类和标签。独立相册结构尚未确认，不默认将相册等同于分类。

实现建议：

- 分类用于主要归属，标签用于多个主题；首版建议单分类、多标签，不预设多级分类。
- 文章列表与照片墙提供分类/标签筛选，只展示访问者有权查看的内容；公开计数不包含草稿和待审内容。
- 分类与标签关联到内容版本，其他用户提交的新增词条和元信息纳入审核，不通过标签绕过全栏目审核。
- 后台管理分类与标签的名称、合并和停用；删除词条不连带删除内容，需处理引用。
- 用户能否创建新分类/标签、标签数量及长度限制待确定；建议分类由站主管理，用户可选已有标签或提交新标签。
- 其他栏目是否复用分类/标签后续按实际需要确定。

## Markdown 文章编辑与预览

已确认：文章使用 Markdown 编辑并预览。

建议实现：

- 桌面提供编辑与预览分栏，手机切换编辑/预览，避免分栏过窄。
- 保存草稿与提交审核分开；预览不代表公开发布，草稿和待审版本仅作者及有权限的管理人员可见。
- 编辑器预览和公开文章使用相同渲染规则；用户内容不执行 MDX/JSX 或脚本，HTML 与链接按统一安全规则处理。
- 上传或粘贴本地图片统一检查 image.upload 权限和用户剩余容量；Markdown 图片语法不能绕过上传或审核流程。外链图片的允许范围及审核快照策略在实现前确定，不能默认把动态外链图片视为已审核资源。
- 提交审核绑定 Markdown 正文与图片资源版本，已发布文章修改后不直接覆盖已审核的公开版本。
- 自动保存、代码高亮与文章目录为可选建议，尚未确认为首版功能。

## 全栏目统一审核流程

以下审核流程适用于其他用户投稿。站主本人内容在基础校验通过后可直接发布；免审只跳过内容审核，不代表跳过身份、输入及资源限制检查。

```text
草稿 → 权限/配额/白名单校验 → 提交版本
                    ├─ AI 未配置 → 待人工审核
                    └─ AI 已配置 → AI 审核
                    ├─ 通过 → 自动发布（建议默认行为）
                    └─ 未通过 / 不确定 / 调用失败 → 待人工审核
                                                     ├─ 通过 → 发布
                                                     └─ 驳回 → 作者修改后重提
```

- AI 未通过转人工已确认；不确定或服务故障转人工为实现建议，避免故障导致自动放行或丢失投稿。
- Next.js 负责权限、审核状态、审核记录、最终发布和数据库写入。
- 建议 Python 的首个职责为调用 AI 并返回结构化审核结果；该职责分配尚待确认。
- AI 仅返回通过/转人工建议、原因及规则标识，不直接授予权限或更改发布状态。
- 审核绑定内容类型、内容 ID 和版本，防止旧审核结果发布修改后的内容。已发布内容编辑后建议创建待审版本，审核期间保留旧的已发布版本。
- 用户提交的文字、图片及元信息作为待审核数据处理，不能将其中的指令当作审核系统指令。
- AI 供应商、审核标准、费用限额、超时重试及并发限制待确定；不在文档存储凭据。

### AI 服务后台配置

已确认：由站主在管理后台配置 AI API 地址、模型和密钥，并可编辑审核规则，便于后续更换服务。具体供应商暂不指定；未配置 AI 时，投稿进入人工审核，不自动公开。

实现建议：

- 配置仅允许站主管理；密钥只在服务端使用，后台保存后脱敏显示，不进入日志、仓库或公开响应。若存数据库，密钥加密保存，主密钥独立于数据库管理。
- API 地址和模型可配置不代表兼容任意协议；实现前明确支持的接口协议，其他供应商通过适配器接入。
- 验证配置的连通性与所需文本/图片能力；模型不支持图片时，对需要图片审核的内容转人工。
- 审核记录关联模型及规则版本；AI 停用、超时或响应无效时建议转人工，不因配置变化自动放行待审内容。
- API 目标地址由服务端校验，限制到允许的外部服务，避免访问内部地址。费用、频率和重试上限在实现时配置。

### 各类内容的审核对象与边界

| 内容 | 审核对象                                  |
| ---- | ----------------------------------------- |
| 文章 | 标题、摘要、正文及插图                    |
| 项目 | 卡片标题、介绍、封面和提交的网址          |
| 照片 | 图片本身、标题和说明；不能仅审文字        |
| 音乐 | 站主导入的网易云曲目 ID、曲名、歌手及封面 |
| 友链 | 站点名称、介绍、图标及提交的网址          |
| 评论 | 评论正文及其中的链接                      |

以上为实现建议：未取得的外站全文、音频及动态页面不能声称已审核；需要审核的图片不可读取或模型不支持时转人工。外链检查不保证目标站未来的内容，音乐完整音频不属于默认 AI 审核范围。

权限校验是审核前置条件，AI 通过不能绕过上传授权或项目白名单。上传待审资源不能出现在公开栏目，草稿/待审预览需鉴权；媒体访问和缓存需遵守同一发布状态。站主本人发布内容已确认免审；普通用户白名单不带来免审资格。建议提供统一待审列表，按类型筛选并保留人工审核原因。

## 网易云音乐体验与接入

已确认体验：

- 同时支持网易云单曲和歌单。
- 站内切换页面保持当前曲目、播放进度、播放/暂停状态与队列；正在播放时继续播放。
- 离开音乐页时缩小成可拖动悬浮播放器。
- 悬浮组件支持暂停、继续和切歌。

实现建议：

- 音乐页完整播放器与悬浮组件共享同一个播放实例；将状态和播放实例放在跨页面保留的应用层，避免路由切换重新创建音频。
- 切歌提供上一首/下一首并遵循当前播放队列。只有一首时禁用无目标的切歌操作；歌单队列获取能力需验证。
- 显示当前封面、曲名和歌手；支持展开播放器、记住悬浮位置。拖动区域与播放按钮分离，适配触摸和窗口尺寸变化，避免与宠物重叠或移出视口。
- 暂停后切页保持暂停；缩小和拖动不改变播放状态。首次播放由用户主动触发。
- 连续播放范围为本网站客户端页面切换，不承诺刷新、离开网站或关闭浏览器后继续播放。
- 播放失败时显示原因和网易云原页面入口；避免队列反复自动重试。

站主从后台导入网易云单曲或歌单。音乐页展示公开曲目、歌词，并用同一个音频实例控制播放。接口配置、可用音源和验证方法见[音乐播放器](./music-player.md)。

站点保存曲目标识和必要展示信息。音频由浏览器直接向网易云 CDN 请求。

验收建议：播放单曲/歌单后跳转文章、项目等页面，验证不中断、不重复播放、不重置进度；在悬浮组件暂停/恢复和切歌；返回音乐页状态保持一致；检查移动端拖动和不可播放曲目的错误状态。

## 网页宠物

已确认形象为平滑的 Q 版动画小焰（晓美焰），长发、黑发带的经典造型，非像素风，可拖动、有交互。建议首版实现待机动作、点击反馈、拖动后贴边、隐藏/恢复及记忆位置；移动端避免遮挡正文和发布按钮。具体服装细节、素材制作方式、动作和台词待确认，不默认加入 AI 聊天。

## 内容模型补充建议

在原候选模型基础上考虑 UserPermissionOverride（含统一图片上传权限）、UserStorageQuota（每用户容量）、ProjectSiteRule（网站允许/禁止规则）、各内容类型的版本记录和 ModerationReview（审核记录）。审核记录保存目标版本、结果、原因和审核者；资源上传记录所有者和大小，便于配额管理。
